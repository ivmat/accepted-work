# Concept notes

These notes explain the ideas the formats rest on. Read them before the format pages, or come back
to them when a format page uses a term you do not know.

The notes have different status. Each note states its own at the top. "An idea" means that nothing
is built for it. "A design" means that parts are built and parts are not. Where something is built
and tested, the note says so.

| note | what it explains |
|---|---|
| [01 Work as typed calls](01-work-as-typed-calls.md) | Work as a program of typed calls. A program or a model can implement the same call. Acceptance checks the result of a call whose implementation cannot be trusted by construction. |
| [02 What a program can decide](02-what-a-program-can-decide.md) | For each field, how much a program can decide today. |
| [03 Class, instance, run](03-class-instance-run.md) | The three layers at which work exists, and why a lower layer never widens its parent. |
| [04 Format principles](04-format-principles.md) | The rules every format follows, and the shared conventions. |
| [05 Glossary](05-glossary.md) | Every term of this repository, in one or two sentences. |
| [06 How to read a format](06-how-to-read-a-format.md) | The parts of a format directory in this export, and how to run a format's tool. |

Suggested order: 01, 03, 02, then 06 before your first format page. Use 04 and 05 as references.
